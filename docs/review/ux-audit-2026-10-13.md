# Lingotorte UX/UI audit — 2026-10-13 (first pass)

**Method:** code read of `apps/web/src/{app.ts,style.css}` + live cognitive walkthrough of the three core tasks against `npm run local` (fixture import → save sentence → create review card → review), viewport 1100×760.
**Evidence labels:** `[observed]` = seen in the running app; `[code]` = established from source; `[inferred]` = my judgement.
**Severity:** blocker / major / minor / cosmetic.
**Scope:** core-task surfaces only (Library, Player, Saved, Review). Practice, Export/Import and Settings were not walked.

This audit is re-runnable with the `ux-audit` skill in `skills/ux-audit/`.

---

## 0. The one-paragraph diagnosis

The app is not ugly because of bad taste — the token palette in `style.css` is coherent and the Player's video/transcript split is sound. It looks unfinished because **roughly fifty CSS class names emitted by `app.ts` have no rule in `style.css`**, so entire views (Review, Saved tabs, Practice, Export/Import) render as unstyled browser defaults inside a dark theme. On top of that, one grid bug makes a status banner swallow the page, and the core "watch → collect → review" loop has three friction points that make the review cards you produce less useful than they should be.

## 3. Task flows — cognitive walkthrough

### Task A: Load a video + transcript
Steps counted from a fresh app: **Nav → Library (1) → choose media (2) → choose target .srt (3) → choose native .srt (4) → Import (5) → auto-switch to Player.** Five steps is fine. Friction is not step count but **noise**: the user must scroll past ~600 lines of provider/ASR UI to find nothing else of use. Empty-state on Player ("Start with owned local media") is good and should be the primary entry.

**Fix direction:** Library = media list + one "Add media" affordance (drag-drop zone accepting video + any number of .srt, auto-assigning target/native by filename suffix). Move "Transcript lifecycle" into a per-media detail/drawer, shown only when the media has no approved transcript.

### Task B: Watch and collect cards
Happy path observed: play → read cue → **Save sentence** (1 click) ✅.
But the result is weak: the sentence is saved **without a meaning**, so the card it produces (see Task C) is "Recognize: X" → reveal "X". The only way to attach a meaning is the Selection panel, reachable by clicking a `timed-word` (needs word timings) — not by Save sentence, not by text-drag.

Also observed: **no feedback at the point of action** (H1); **accidental saves via drag** (H4).

**Fix direction:** one collect gesture → one lightweight inline card (text, meaning field focused, notes collapsed, "Save" + Esc). Both "Save sentence" and drag-select should open it. Show a 2-second toast "Saved · Undo".

### Task C: Review cards
Walkthrough: Saved → My Sentences → **Create review card** (per item!) → Review → Show answer → rate.
- **Cards are not created automatically.** Every saved item requires a manual "Create review card" click, one at a time, and it only ever uses the *first* occurrence. `[code]` `app.ts:4104-4116`. For a personal SRS tool this is the single biggest streamlining win: saving should enqueue a card by default (opt-out per item).
- **Recognition card with no meaning has no answer.** Front: "Recognize: Cześć, to jest lokalny test." Back: the same sentence + native cue line (from the native track, if present). Fine *when* a native track exists; empty otherwise. `[observed]`
- Review screen shows the content hash and "state: new • due: 2026-10-13 20:31:34 UTC" — raw ISO UTC for a learner in New Haven. `[observed]`
- Rating buttons (Again/Hard/Good/Easy) are correctly styled and keyboard-reachable ✅. No 1-4 keyboard shortcuts though.

**Fix direction:** auto-create recognition card on save; Review shows "N due today" as the hero number; hide scheduling internals behind a disclosure; add `1-4` / `space` shortcuts.

## 4. Prioritised fix list (do in this order)

1. **Fix the grid bug (V2)** — 1 line: add the sync banner *inside* the header or change `grid-template-rows` to `auto auto 1fr auto`. Instantly removes the giant empty box.
2. **Style the unstyled classes (V1, V3, V4, V5)** — Appendix A is the checklist. Expect ~200 lines of CSS. This alone will make the app look finished.
3. **Auto-create a review card on save (Task C)** and make "Create review card" a bulk/"also add to review" toggle.
4. **Unify the collect gesture (H4, H5, Task B)** — Save sentence and drag-select both open the Selection card; never save on `mouseup`.
5. **Local feedback on save (H1)** — toast with Undo.
6. **Fix subtitle/controls collision (V6)** — either drop native `controls` (you already have a full custom row) or pad the overlay bottom by the control bar height.
7. **Collapse the Transcript lifecycle panel (H7)** into a disclosure, hidden when the current track is approved; give Library an actual media list (H8).
8. **De-jargon labels (H3)** and hide hashes / token spans behind "details" (V8).
9. Typography pass: cue text ≥ 1.05rem, chrome ≥ 0.8rem, one display face for h1/h2 (V10, V12).
