# lt-sor — LAN request-authenticity implementation handoff

Build one default-deny admission boundary and one process-scoped paired transport for the private app.
Use exact public Host/Origin configuration, Host-preserving Docker `/api` proxy, and private local capability delivery.
Riskiest assumption: the operator trusts the plain-HTTP LAN, UI/proxy and Docker administrators; this is not encrypted or multi-user security.

### Public/internal tuple examples (configuration descriptions, not existing options)

Docker LAN: configured public origin `http://192.168.1.40:5173`, public Host `192.168.1.40:5173`; web socket listens container `0.0.0.0:4173`; upstream socket target `http://api:5174`; API bind `0.0.0.0:5174`. Forwarded Host remains `192.168.1.40:5173`, NOT `api:5174`. Browser destination is its captured public origin and `/api/...`. A configured DNS origin is another exact entry, never an inferred alias. Probe `127.0.0.1:5174` admits only minimal health. Direct native default: service `http://127.0.0.1:5174`, UI `http://127.0.0.1:5173`; native `port: 0` first validates configuration/private delivery, binds with application admission DISABLED, obtains the actual listening port and freezes exact authority, then initializes resources and enables admission only at readiness (contract §3). No request, including health/preflight, dispatches or discloses private bytes during either post-bind interval. Fixed-port native/Docker policy remains frozen before listening. IPv6 uses brackets. HTTP port 80 is serialized without an origin port; Host default-port handling is explicitly constrained in the contract.

Nonsecret configuration can contain public origins, proxy target, bind and delivery mode; capability MUST NOT be an environment/Compose/config value. Do not dump config to retrieve it. LAN pairing warns that data and bearer travel unencrypted and that selecting a hostname/IP asserts operator trust rather than proving privacy/authenticity.

## 2. Known unknowns and how the plan absorbs them

- **New IPC delivery is unimplemented/unqualified.** Node Unix-domain sockets plus tmpfs/0700/0600 provide a small feasible Linux-local boundary, not proof of a working helper. Verify actual tmpfs mount/ownership, receiver availability and private controlling-TTY handling with injected failures. Reject redirected helper output; no secret stdout/stderr/config/env. If the boundary cannot be proven, block detached startup. Dedicated ephemeral IPC setup is the only allowed pre-state filesystem activity. Socket readiness precedes state/scratch/model activity; operator retrieval can happen afterward because secret delivery is already available locally. Docker-admin/same-uid compromise is excluded, not solved.
- **Vite proxy behavior must be bound by tests, not its default.** Baseline proxy has no explicit Host validation or `changeOrigin` setting. Specify preservation and ingress policy explicitly; reject raw duplicate Host before proxy normalization, or return a parser rejection. Strip forwarded fields. Proxy must not log Authorization or request bodies. Test public external port != internal port, good bearer + bad Host, and direct internal-authority denial. If the chosen Vite hook cannot inspect original ingress framing safely, fail review and choose a narrow ingress adapter, not a wildcard/forwarded-header exception.
- **Browser local-network policy varies.** Record real supported browser/version and prompts. A browser block is not proof the service gate rejected; server before/after oracles still mandatory. Native direct mode is supported under explicit configuration; no browser security disabling. Plain HTTP LAN may lack persistent file handles: ordinary synthetic file import is the fallback, not permission for TLS deployment.
- **Restore APIs are not present at this baseline.** `lt-3xg` is planner-only; it adds no routes now. Preserve restore contract §8 split: domain/storage/core implementation can proceed independently, with later route wiring through the common gate. Do not create a request/restore dependency cycle. `lt-2t4` reconciles and requalifies integrated preview/commit routes, revision/audit behavior and clients. Unknown future routes stay nondispatchable; earlier `lt-sor` receipts do not qualify them.
- **No application qualification is claimed here.** A24–A26 remain mandatory real-browser gates later, including Docker LAN same-origin and negative foreign/null origin flows. Node/raw HTTP/JSDOM are complementary, never substitutes.

## 4. The mechanical work (after independent contract review only)

1. **Request worker** implements immutable discriminated native-direct/Docker-proxy policy, raw-header/target parser and route table; all private reads/effects behind pre-dispatch admission. Preserve existing state revision/business/provider checks. No domain/storage/core edits by this worker.
2. **Request worker with runtime coordination** implements 32-byte OS-random capability, constant-time exact validation, private native callback/TTY delivery, Docker memory/Unix-socket receiver and controlling-TTY helper. Fail before bind or state/scratch/model effects if receiver/config unavailable. Implement the contract §3 native `port: 0` disabled-bind → actual-port authority freeze → resource initialization → readiness sequence, with no interval dispatch/private disclosure/request effects or replay; close listener on failure and separately qualify startup-owned initialization rollback/disposal, preserving pre-existing data. Fixed-port native/Docker keep pre-listener exact-policy requirements. Requalify startup/restart/shutdown with injected failures and A04/A30 paused-interval synthetic requests. Proposed files under service/scripts plus Compose/Vite changes require parent-assigned ownership before concurrent runtime edits.
3. **Request worker** introduces one memory-only captured paired transport and masked Settings pairing. Model and snippet requests use `redirect:'error'`, `credentials:'omit'`; URL edit/disconnect/401 invalidates loops/autosave, no automatic mutation replay; captured requests cannot retarget or update a replacement pairing. No extra auth/account framework.
4. **Request worker** migrates native helper callers/test setup and route-envelope examples; adds generated finite A01–A30 expansions, all eight job controls/Host/Origin/capability denials, private R02/R03/R06/R08 disclosure checks, LRU/body/media negatives, paused worker comparison, actual request-independent CORS and redirect/egress spies. Applicable classes only; counts reported from execution.
5. **Independent spec then quality reviewers** review exact content-bound candidate within the two remaining cycles of the three-cycle total allowance (correction 1/3 already consumed). **Browser/runtime qualifier** runs supported real-browser A24–A26 and synthetic detached/LAN/direct journey; receipts include version/actual Origin/Host/preflight/prompt behavior, image/source identity, no secrets/screenshots of capability, provider-fake counts and skipped gates. No host installs/models/real learner/media/provider actions.
6. **Parent / lt-2t4 integrator** joins restore branch, inventories newly introduced private preview/commit routes and clients, gates them, and qualifies complete request + restore + durable revision/audit contracts. Restore worker owns domain/storage/core restore semantics; planner `lt-3xg` remains route-free. Do not require restore application work to finish before request admission implementation or vice versa; integration closes the join, not historical assumptions.

### Acceptance oracles, not merely HTTP status

Seed disposable snapshot/revision/audit, waiting job, completed snippet, sentinel file hashes and gated runner. Baseline after startup and before shutdown. Each policy/envelope denial compares persistence save/transaction/audit/revision, full jobs/map/status/ID allocation, snippet access counter/LRU/map, filesystem content manifest, lifecycle/in-flight set and runner/provider calls; checks no private body/token. Authorized controls must demonstrably change the relevant state. Paused worker denial returns without drain/cancel and releasing it produces the control publication outcome. Safe isolated transport denial diagnostics cannot affect application counters. A01–A30 are requirements, NOT executed results.
