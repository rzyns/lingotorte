## Changed existing checks (named, with rationale; none weakened)

* Migration/schema suites (`durableReplace`, `durableRevision`, `legacyMigrationQualification`, `localPersistence`,
  `ltfoe31MeaningSource`, `practiceSqliteMigration`): expect schema 13 and the appended `learner_operations` migration;
  synthetic "future migration" fixtures move from 13 to 14; v12 downgrade fixtures also drop the three v13 tables.
* `saveSafety`: restart readback is equal except `operations.incarnation`, which must now change on restart (fence).
* `ltfoe31MeaningEdit`, `ltfoe34GlossUi`: `receipt.item` is optional on the widened receipt type (non-null asserted).
* `localServiceSync` stale-writer test: an operation alone no longer makes another browser's document stale (that is
  the feature); the test now makes `first` perform a document edit, so the stale CAS refusal is still exercised.
* `transcriptLoading`: (a) the key-order-independent comparison recognises a content-identical cache (no false Keep/Load
  choice, the lt-192.2 finding); other media's bundles still stay pending. (b) An unchanged document sends no redundant
  `PUT /api/state` after verified bundles.
* `lt1922RecoveryRehearsal`: seeds through the unpaired document path it rehearses (paired vocabulary is operations
  now); reconnect after a lost ack is recognised as content-identical instead of a false choice (answers lt-192.2's
  open question); the stale-sentinel step now expects the operation fence's `409 operation-owned-rows` with Restore
  (merge) guidance after the two write-once bundles, instead of a bundle 409.
* Generated workflow catalog (`docs/workflows/as-is/structure.yaml`, `docs/workflows/generated/index.md`): regenerated
  with the repo's own extractors (new route and Saved-view control).

## Failures, retries and fixes during the work (bounded)

1. First full run: 2 failures — stale generated catalog (regenerated) and the two-tab test, which exposed a real bug: a
   sessionStorage-only tab id is copied to a *duplicated* tab, letting two tabs share a dispatch owner. Fixed by
   adopting the remembered id only while holding a Web Lock on it.
2. Browser proof iterations fixed the proof script only (selector strictness, measurement windows that ignored the
   flush performed by pairing, cap/duplicate ordering); one product finding there: none beyond (1).
3. Windows tooling wrote CRLF into LF files; all touched files were normalised to LF before the final runs
   (`git diff --stat --ignore-cr-at-eol` equals the plain stat).
