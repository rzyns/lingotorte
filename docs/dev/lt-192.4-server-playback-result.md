### Corrections and discriminators

1. **Early cancellation:** dispatch/reservation reject an already-closed client; pending-open and before-pipe checks retain exactly-once descriptor/slot release. The native-HTTP regression holds admission at `deliveryReady`, closes the client before reservation, releases readiness, repeats sixteen times and verifies capacity remains available. This covers the previously missing boundary, not only cancellation during `open`.
2. **Mint/revoke ordering:** background and recovery mints are tracked per model. Revoke blocks new mints and drains outstanding responses before its final DELETE. Unsettled/timed-out mints make the result explicitly unconfirmed even if DELETE succeeds; freshness checks are not used as a substitute for undoing browser `Set-Cookie`. Tests cover before-commit, response and continuation barriers, bounded ignored-abort behavior, and Forget/Disconnect semantics. The browser proof delays a background mint, confirms no premature DELETE or success claim, then confirms both old and late cookie replays are 401 after successful revocation.
3. **401 honesty:** revoke no longer treats 401 as proof of restart. The native-browser test makes delivery temporarily unready, observes the unconfirmed warning, restores readiness without restarting and proves the held cookie still returns 206.
4. **Visible playback error:** the message is rendered inside the stage rather than below a full-height video. The proof requires its bounds to lie inside the stage and its center to be topmost, in addition to text/role checks. Screenshots remain local evidence and require independent visual review.
5. **Bounded recovery:** metadata alone no longer resets the re-mint budget; verified time advancement while playing ends the error sequence. The worker's retained red corrupt-MP4 run observed **214 mints / 214 metadata-error cycles in eight seconds**. The current native proof exercises both corrupt MP4 `mdat` and WebM blocks: each raises errors after metadata, makes exactly one re-mint and ends with the decode explanation rather than looping.

## What was implemented

- **Server.** `mediaSessions.ts` (64-value in-memory cap, oldest-by-mint eviction, no TTL/touch, `HttpOnly; SameSite=Strict; Path=/api/media/`, `Secure` only for an HTTPS public origin). `managedMedia.ts` (library preparation after `assertLibraryPath`, M3, M4 GET/HEAD from a single `O_RDONLY|O_NOFOLLOW|O_NONBLOCK` descriptor checked with `fstat` against the registry row, BigInt-safe single Range, HEAD = full representation always and bodyless on every status, `nosniff`/CORP same-origin/`no-store`, 16 shared slots reserved synchronously, pending opens tracked and re-checked after each await, exact-once release with no close retry, prompt shutdown). Schema 14 adds only `managed_media_blob` (migrations 1–13 and their checksums unchanged); the registry is outside learner save, snapshot, restore and export. Admission: duplicates → 400, then M4-only `Sec-Fetch-Site` → 403, then a present `Authorization` decides alone, else exactly one valid `lt_media` pair; M1/M2 need the bearer and exact same-origin. Library unset ⇒ M1–M4 absent (404), status `managedMedia.available: false`.
- **Client.** `serverMedia.ts` derives one playback source (local object URL ▸ confirmed server copy ▸ relink/honest message; a `managed:` label never becomes a `src`); M1 after status OK only in the exact same-origin profile; one M3 per media per pairing; native-video failure ⇒ checking-access ▸ M3 ▸ (401 pair again | missing | unreachable | complete ▸ one re-mint ▸ reload); Forget and Disconnect revoke (M2) first and disclose an unconfirmed revocation. The transport sends `credentials: 'same-origin'` only for `/api/media/session` and only to the exact page origin; everything else stays `'omit'`.

## Red → green and mutations

Regressions found by the real-browser proof, each written as a failing JSDOM test first, then fixed:

1. **Library relink gate** (`lt1924PlaybackSource`): after a reload the current asset's Library row offered only Relink although its server copy existed (the Library never ran M3). Red: `expected [] to have a length of 1`, `expected undefined to be 'complete'`. Fix: the Library view runs the same bounded once-per-pairing M3; `mediaAssetNeedsRelink` drops Relink for a non-current asset only when this pairing already confirmed a complete copy (no per-row M3).
2. **Restart honesty** (`lt1924MediaRecovery`): after a restart, a never-checked asset got M3 401 and showed a bare Relink with no reason. Red: `expected undefined to be 'Pair again to play server media.'`. Fix: an M3/M1 401 sets a transient `pairingLost` hint (cleared by the next status OK) so the stage says "Pair again".

## Failures, retries and fixes (bounded, retained)

- **Full-suite run 1 on the first final image** (`sha256:72fb5b80…`): 2 failed in `lt1924ServerMediaRoutes` (C1 and N03/N04), run 2 passed. Cause, from the assertion diff: the zero-effect *before* snapshot was taken while the previous successful 200's slot and stream were still being released (`slots:1, streams:1`), and the *after* snapshot saw them released (`0`). The denial added nothing; the oracle raced the asynchronous release. Fix: `effects()` waits (bounded, 5 s) for slots, streams and pending opens to settle to 0 first, so a denial that leaks one still fails. Twelve parallel stress runs (old and new oracle) did not reproduce it on demand; it was observed once. Both full runs on the rebuilt final image passed.
- `lt1924ManagedLibrary` `/proc/self/fd` count was read before socket teardown settled (one extra fd under load): now polled to the baseline, bounded; a leaked descriptor still fails.
- Proxy-flow helper used the loopback port as `Host` while the service's public authority was the proxy origin: corrected to the configured public authority.
- Workflow catalog (`docs/workflows`) was stale after source line moves: regenerated in the container; `--check` passes.
- Proof harness issues (not product): `context.cookies(origin)` filters by path (cookie only listed for `/api/media/`); a second import with the same title tripped the existing name-conflict guard (renamed); Chromium buffered whole small files so eviction/restart produced no request (now uses never-loaded assets and an unbuffered gap with a 90 MB file); Playwright refuses >50 MB buffers (path passed instead); ORB hides headers from Playwright's request API (CDP ExtraInfo used); one rerun copied media from an MSYS path and silently fell back to the 2 s fixture, failing P3/P4/P7 — those runs are discarded and not counted.
